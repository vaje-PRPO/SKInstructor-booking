## ADR-001: Prehod na multi-repo arhitekturo in OpenAPI spec-first pristop

**Kontekst**
Sistem SKInstructor je sestavljen iz štirih ločenih domen (Katalog, Rezervacije, Plačila, Obvestila). Iskali smo optimalen način za organizacijo kode v skupini, da bi preprečili konflikte pri potrjevanju kode (Git merge conflicts) in omogočili standardizirano komunikacijo med storitvami, še preden se začne samo programiranje poslovne logike.

**Odločitev**
Odločili smo se za **multi-repo arhitekturo**, kjer ima vsaka mikrostoritev (tudi `SKInstructor-booking`) svoj povsem neodvisen GitHub repozitorij z lastno strukturo. Hkrati smo sprejeli odločitev za **OpenAPI spec-first pristop**, kar pomeni, da je pogodba za API vnaprej definirana v datoteki `openapi.yaml`, ogrodje vmesnikov in modelov pa se samodejno generira ob prevajanju (Maven).

**Posledice**
* **Prednosti:** Popolna neodvisnost razvoja in lokalnega testiranja, jasna izolacija odgovornosti, avtomatsko zgenerirani API modeli zmanjšujejo možnost človeških napak.
* **Slabosti:** Potrebno je vzdrževati več repozitorijev ločeno. Za celovit preizkus celotnega sistema bo potreben ločen krovni repozitorij z orodjem Docker Compose, ki bo povezal vse storitve hkrati.
